# Skill: vet a posting

Always first. Most postings should die here, before any CV work.

## JD analysis framework (mandatory for every JD) `HO`
1. **What they're really looking for:** key requirements, and the real role underneath the title.
2. **Company pain points:** what problem are they hiring to solve?
3. **Fit:** strong matches AND gaps, honestly, against confirmed facts only.
4. **Positioning:** where to lead, how to frame gaps, which story serves this role
   (the library's Story Selection Guide).
5. **ATS keyword coverage:** which JD terms Kfir's background covers and which it doesn't.
6. **Clarifying questions:** ask them as buttons/multiple choice before drafting anything. Never
   assume experience; ask.

Never ask about role priority or how serious the application is. Kfir applies widely. `HO`

## Steps
1. Check `jobs/tracker.md` — already vetted? Say so and stop.
2. Open the posting live. Closed / reposted / aggregator-only → say so.
3. Fill the facts (Unknown beats a guess): role, pay range, location/remote, reports to, what the
   company does, stage/funding, approx employees.
4. **Auto-skip check** (`career-context.md` §5 Not interested): Quebec exclusion clauses,
   Toronto-only, US-only, 10+ year minimums, hard domain gaps.
5. **Title vs real duties:** read the responsibilities, not the title. Flag anything that is really
   a sales/quota, support-only, or project-coordination job (check `career-context.md` §5 Not interested).
6. Check hard filters in `career-context.md`: location/remote, work authorization, pay floor, seniority.
7. Give a **one-line verdict**: **Apply / Stretch / Skip** + the reason.
8. Pick the track (PM / CSM) and pull **8–12 key terms** a recruiter or ATS would match on.
9. Add a row to `jobs/tracker.md` (status *Sweep lead* or *Interested*; *Passed* for skips).
10. If Apply/Stretch: create `jobs/YYYY-MM-DD Company/notes.md` from `jobs/_template/notes.md`.

## Output format
```
<Company> — <Role>  |  <Apply / Stretch / Skip>
Why: <one line>
Pay: <range or Unknown> | Remote: <…> | Stage: <…> | Size: <…>
Real duties: <one line>   Track: PM / CSM
Key terms: a, b, c, …
```
